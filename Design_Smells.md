# Design & Code Smells Analysis

## 1. God Class
A class that handles too many responsibilities such as order, billing, and UI logic together.

## 2. Long Method
Some methods perform multiple tasks instead of single responsibility.

## 3. Tight Coupling
Modules like order and billing are highly dependent on each other.

## 4. Duplicate Code
Similar logic is repeated in multiple activities.

## 5. Large Class
Some classes contain too many methods and data fields.

## 6. Feature Envy
Some classes use data from other classes excessively instead of their own.

## 7. Lack of Separation of Concerns
UI, logic, and data handling are mixed in some components.

## Conclusion:
The system needs refactoring using SOLID principles to improve maintainability, scalability, and readability.
